# Order Miniapp

服装档口订货、配货、退货与对账微信小程序模板，采用 Taro 4、React 18、TypeScript 和微信云开发。

这是独立脱敏的开源版本，不是实际经营数据库的备份。全部样例商品和业务数据为演示内容；不包含原运营方客户资料、订单、账单、商品图片、管理员身份、云环境或密钥。

## 功能

- 客户端：微信登录、商家资料注册和审核状态、分类选款、单双列、规格与数量输入、订货车、订单、退货申请、个人中心。
- 档口端：商品维护、实配出库与入账、交付确认、异常恢复、参考库存、客户审核、账单调整与导出。
- 人员权限：员工申请、主管理员审核、停用恢复，财务权限单独控制。
- 导单：截图与慧策公开链接任务、客户外部款号映射及人工复核；可选本地 Ollama worker。
- 交互：加载状态、空状态、失败重试、错误请求编号。

## 本地运行

需要 Node.js 18 或以上、npm、微信开发者工具。

```sh
npm ci
npm run typecheck
npm test
npm run build:weapp
# 持续编译
npm run dev:weapp
```

在微信开发者工具导入仓库根目录，编译目录为 `dist/`。`project.config.json` 默认使用游客 AppID；微信身份、手机号、云函数等真实功能需要你自己的小程序 AppID。

未配置云环境时使用演示模式，只供浏览界面，不能用于真实记账。云环境配置后从云端读取数据，失败时不应混入演示账单。

## 部署自己的云端

1. 将 `.env.example` 复制为 `.env.local`，填写自己的 `TARO_APP_CLOUD_ENV_ID` 和云函数名称。默认函数名为 `api`。
2. 在微信开发者工具填写自己的 AppID；确认云环境与该小程序绑定。
3. 参考 `cloud/collections.json` 建立集合和索引；数据库直连权限按 `cloud/database.rules.json` 限制，业务经云函数鉴权。
4. 部署 `cloudfunctions/api` 并安装依赖；在服务端环境变量 `STALL_OPENIDS` 中填写自己的主管理员 OpenID，逗号分隔。仓库不预置管理员。
5. `cloudbaserc.json` 中的环境 ID 是占位符，使用前必须修改。前端函数名称须与实际部署名称一致。
6. 管理员可用已有 `admin.seed` 接口初始化三款虚构示例商品；不要在已有生产库盲目初始化。自行上传有权使用的商品图片。
7. 填写自己的运营主体、客服方式、隐私说明和微信后台隐私指引。示例协议不能直接作为正式运营协议提交审核。

取得自己的 OpenID 应通过受控的微信云开发调试流程，不要将其他用户的身份信息粘贴到公开 Issue。不要把 `STALL_OPENIDS` 或任何云密钥提交到仓库。

## 导单服务

`tools/local-import-worker` 是可选识别服务，需要单独安装依赖，按其 `.env.example` 配置。默认访问本机 Ollama；需要实际安装对应模型和 Chrome。云端任务建立成功不代表识别模型在线。

worker 使用服务端云凭据访问任务，密钥仅保存在受控运行环境。识别结果必须人工检查款号、颜色、尺码、数量后再下单。当前没有监听微信群、自动发群消息、微信支付或原路退款的完整实现。

## 业务口径

客户下单只建立需求与占用，实际配货确认后入账。退货照片通过不抵账，收到实物并清点确认后才抵扣，可售数量才回库存。库存为参考总量，尚非严格颜色尺码库存。群内上货、加货、退货消息由人工与业务记录对应，避免重复记账。

## 使用边界与安全

这不是拿来即用的生产服务。上线前请进行权限隔离、隐私授权、并发和重复点击、弱网断网、图片上传及 Excel 导出真机测试。通知开关目前是本地偏好，不代表已接通订阅消息。模板的商品图片迁移接口只适用于你自有的可信图片来源，不要接入不可信远程 URL。

项目不包含原项目的商品采集脚本、品牌资产和内部运营手册。第三方依赖按各自许可证使用；部署产生的微信、云开发和模型服务费用由部署者承担。
